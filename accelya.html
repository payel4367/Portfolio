Problem

Cargo messaging lived in a legacy desktop client: every search field, result, sender, recipient and reference panel on one crowded screen, with key actions hidden in right-click menus.

Solution

A web redesign on a shared layout: a focused search with advanced options on demand, clean result tables with row actions, and details and child records in modals.

Key trade-off

Analysts rely on dense data. We kept the data, but showed the common fields first and put the rest one click away.

My role

I co-designed 8 flows with Shruti, across UX and UI: message search, compose, forwarding, message format, element definition, EDIFACT envelopes and double signature.

01 · Problem

Powerful, but hard to read.

Cargo systems exchange a constant stream of standard messages between airlines, handlers and partners. The tools to search, compose and configure them worked, but they were built for another era.

The legacy client packed search, results and message details into one window, in small type and grey panels. Configuring EDIFACT envelopes meant editing a parent table and a child table side by side, and adding a child record was tucked inside a right-click menu. The redesign had to keep all of that power while making it easier to find and use.

01

Everything at once

Search fields, results, sender, recipients and references all competed for space on a single screen.

02

Hidden actions

Key steps, like adding an envelope detail, sat behind right-click menus that were easy to miss.

03

No shared pattern

Each module looked and behaved a little differently, so every new screen had to be learnt from scratch.

How might we

…keep the depth cargo analysts depend on, while making every screen follow one clear pattern: search, scan, act?

04 · Flows

The flows I co-designed.

The design file is organised by module, with each flow laid out screen by screen and annotated for developers. These are the flows Shruti and I designed together.

Message search

Find any message, fast.

A short search covers the everyday case: message ID, date range and status. Advanced search opens the full set of filters, and reference details such as origin, destination and airline prefix sit in their own table.

  • Toggle between message search and alerts
  • Expand any row to see its child messages
  • View or reprocess from the row
Message details

Sender, recipients and content, side by side.

Details open in a modal instead of a new window: sender and recipients as cards, the raw message below, and attachments you can download one by one or all at once.

Compose message

Write in plain text, or start from a template.

Pick participants or a group, then choose plain text or a template. Attachments and additional addresses are added from the top, the format is verified before sending, and a toast confirms each step.

EDIFACT envelopes

Parent and child records, without the right-click.

Envelope details now open from a visible row action into a modal. The parent record stays on top for context, each field has a help tip, and an empty state shows what to do first.

06 · Configuration

Set up once, trust it every day.

Behind every message are rules: who signs it, where it is forwarded, which format version goes out. These screens follow the same search-and-table pattern, so admins already know their way around.

07 · Handoff

A file built for developers.

The Figma file is the developers’ source of truth. A file log tracks every feature, who owns the UX and UI, and which release it lands in.

Each flow sits in its own section, with explanation bars above the screens that say what happens, in what order and in which state: adding, editing and deleting rows, empty states, confirmations and success messages.

08 · Reflection

What enterprise redesign taught me.

In enterprise tools, people already know the old system by heart. The job isn’t to remove what they rely on, but to make it easier to find.

Working from the legacy screens first, and keeping every field accounted for, made it easier to agree with the team on what could move behind a click and what had to stay visible.
